Boot handoff into C, and the kernel's main entry point

Defined in: src/kernel/entry.asm, src/kernel/kernel.c

Together these two files are the whole boot-to-shell handoff: one assembly label stage2 jumps to, and one C function it calls.

Function detail

entry (assembly label, src/kernel/entry.asm)

What stage2 jumps to after loading KERNEL.BIN. Sets ds/es/ss to cs — the kernel's single 64 KB segment, where code, data and stack all live together — and the stack pointer to near the top of that segment, then calls kmain(boot_drive) with the boot drive number stage2 left in dl. If kmain ever returned (it doesn't, since shell_run never returns either), execution falls into an infinite cli; hlt loop rather than running off the end of the binary into whatever garbage follows.

dl
(register, not a C parameter) Boot drive number, as left by stage2.
Returns
Never returns.

void kmain(uint16_t boot_drive)

The C side of the handoff, and the only function in kernel.c. Clears the screen, prints the banner, calls fat_init((uint8_t)boot_drive) — printing a warning rather than halting if it fails, so the shell still starts even without a working filesystem — then calls shell_run().

boot_drive
BIOS boot drive number, passed in from entry's argument push.
Returns
Never returns (shell_run doesn't return; kmain has a defensive halt loop after it as a backstop).
