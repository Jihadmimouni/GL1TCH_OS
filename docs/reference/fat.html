fat

FAT12 filesystem driver

Defined in: src/kernel/fat.c, src/kernel/fat.h

Depends on x86.h (disk I/O) and kstring.h (name comparison/copying). Owns all on-disk and current-directory state as file-scope statics — nothing here is reentrant, which is fine since the kernel has exactly one execution context. See architecture.html for how this module models the root directory and subdirectories as one abstraction, both for reading and (since the write path was added) for writing.

Types

fat_dirent_t
{ char name[13]; uint8_t attr; uint16_t cluster; uint32_t size; } — a directory entry as handed to callers: name is already formatted as a display string (e.g. "KERNEL.BIN", no trailing padding), attr is the raw FAT attribute byte (check attr & FAT_ATTR_DIRECTORY), cluster is the first cluster of its contents, and size is only meaningful for files (FAT stores 0 for directories; use cluster-chain traversal to size one of those).
fat_visitor_t
int (*)(const fat_dirent_t *entry, void *ctx) — return nonzero to stop iteration early (the returned value becomes fat_list_cwd's/the internal iterator's return value).
fat_sink_t
void (*)(const uint8_t *data, uint16_t len, void *ctx) — called once per sector of file data read by fat_read_file; data is not NUL-terminated and may contain any byte value.

Function detail

int fat_init(uint8_t drive)

Call once, with the boot drive number the bootloader handed the kernel. Resets the disk, asks the BIOS for real geometry via x86_disk_params (falling back to 18 sectors/track and 2 heads — standard 1.44 MB floppy values — if the BIOS reports 0 for either), reads the boot sector and parses the BPB fields it needs directly by byte offset (bytes/sector at 0x0B, sectors/cluster at 0x0D, reserved sectors at 0x0E, FAT count at 0x10, root entries at 0x11, sectors/FAT at 0x16 — read as raw bytes rather than through a C struct, which sidesteps any compiler padding/alignment surprises), derives the root directory and data area locations, and caches up to 9 FAT sectors (this project's fixed 1.44 MB floppy layout) in a static buffer.

drive
BIOS boot drive number.
Returns
1 on success; 0 if the boot sector or any FAT sector couldn't be read.

void fat_list_cwd(fat_visitor_t visitor, void *ctx)

Calls visitor(entry, ctx) for every real file/subdirectory entry in the current directory — volume labels, long-filename fragments, deleted entries, and ./.. are filtered out before the visitor ever sees them. shell.c's cmd_ls is the only caller.

visitor
Called once per entry; return nonzero to stop early.
ctx
Opaque pointer passed through to visitor unchanged.
Returns
Nothing.

void fat_get_cwd(char *out)

Writes the current path ("/" at the root, "/sub/dir" otherwise) by joining the names on the internal directory stack. Used both for the pwd command and to build the shell's prompt.

out
Destination buffer; must be large enough for 8 path levels of up to 12 characters each plus separators (104 bytes comfortably covers it).
Returns
Nothing.

int fat_change_dir(const char *path, const char **err_msg)

Resolves path (absolute if it starts with /, otherwise relative to the current directory) one /-separated component at a time, against a temporary copy of the directory stack. Only if every component resolves — and is actually a directory, and the stack doesn't exceed its fixed 8-level depth — does it commit that copy back as the real current directory. So a failing multi-component path like cd a/b/nope leaves the shell exactly where it started, never partway into a/b. . is a no-op; .. pops a level (clamped at the root, so it never underflows).

path
Absolute or relative path, /-separated.
err_msg
Out: set on failure to "no such directory", "not a directory", or "path too deep".
Returns
1 on success; 0 on failure, with the current directory left unchanged.

int fat_find_file(const char *path, fat_dirent_t *out, const char **err_msg)

Walks path the same way as fat_change_dir, but only the last component needs to exist (it's returned in *out regardless of its type, then rejected with "is a directory" if it turns out to be one); every earlier component must still be a directory. .. mid-path is deliberately unsupported here (a distinct error message is returned) since this function, unlike fat_change_dir, doesn't carry a directory-stack copy around to pop.

path
Absolute or relative file path.
out
Out: the resolved entry, only written on success.
err_msg
Out: set on failure to "no such file or directory", "not a directory", "is a directory", "'..' is not supported in file paths", or "no file specified" (empty path).
Returns
1 on success; 0 on failure.

int fat_read_file(const fat_dirent_t *entry, fat_sink_t sink, void *ctx)

Walks entry's cluster chain, calling sink(data, len, ctx) once per sector read. len is capped at the file's remaining declared size, so the last, possibly-partial sector of a file never hands back trailing garbage past EOF. shell.c's cmd_cat is the only caller, with a sink that re-inserts \r before each \n for display.

entry
A file entry previously returned by fat_find_file or fat_list_cwd's visitor.
sink
Called once per sector of data.
ctx
Opaque pointer passed through to sink unchanged.
Returns
1 on success; 0 if a sector read failed partway through.

int fat_mkdir(const char *path, const char **err_msg)

Resolves every component but the last (which must not yet exist) via the same directory-walking logic as fat_change_dir, allocates one fresh cluster and zeroes it (an empty directory needs no ./ .. entries, since the cwd stack is kept in memory rather than read off disk — see architecture.html), then writes a new 32-byte directory entry pointing at it. If the parent is the fixed-size root and has no free slot, this fails outright; a subdirectory parent instead grows by chaining on one more cluster.

path
Absolute or relative path; only the final component is created.
err_msg
Out: set on failure to "no such directory", "not a directory", "invalid name", "already exists", "directory full" (root only), or "disk full"/"disk error".
Returns
1 on success; 0 on failure.

int fat_create_file(const char *path, const char **err_msg)

touch semantics: if a file of that name already exists, succeeds as a no-op without touching its contents; if a directory of that name exists, fails. Otherwise writes a new zero-length, zero-cluster directory entry, the same way fat_mkdir does except with no cluster to allocate.

path
Absolute or relative path.
err_msg
Out: set on failure to the same directory-resolution errors as fat_mkdir, plus "is a directory".
Returns
1 on success (including the already-exists-as-a-file no-op); 0 on failure.

int fat_write_file(const char *path, const uint8_t *data, uint32_t len, int append, const char **err_msg)

The one function that handles all four combinations of "file exists or not" and "overwrite or append". Overwriting an existing file frees its old cluster chain first (free_chain) and reuses its existing directory-entry slot; creating a new file finds or grows a free slot the same way fat_mkdir does. Appending walks to the last cluster of the existing chain, tops it up with a partial sector-granular write (partial_write_in_cluster) before allocating any new clusters, so it never wastes the tail of a partially-used cluster. The FAT is only flushed to disk once, after every cluster change for this call has been made in the in-memory copy, and the directory entry (cluster + size) is written last — so a write that fails partway through never leaves a directory entry pointing at a partially-updated chain.

path
Absolute or relative path; created if it doesn't exist.
data
Bytes to write; not required to be text or NUL-terminated.
len
Number of bytes in data.
append
0 to discard any previous contents first; nonzero to add data after them.
err_msg
Out: set on failure to "is a directory", any of fat_mkdir's directory-resolution errors, or "disk full"/"disk error".
Returns
1 on success; 0 on failure (the directory entry is left as it was before the call).

int fat_remove(const char *path, const char **err_msg)

Looks up the entry the same way fat_find_file would, but accepts directories too. A directory must be empty (dir_is_empty, which stops at the first non-deleted, non-terminator entry) and must not be the current directory or an ancestor of it on the cwd stack — otherwise the shell would be left pointing at a cluster that's about to be freed and potentially reallocated to something else. On success, the entry's whole cluster chain is freed in the FAT and its directory-entry byte is set to 0xE5 (the standard FAT "deleted" marker), exactly what scan_sector already knows to skip.

path
Absolute or relative path to a file or empty directory.
err_msg
Out: set on failure to "no such file or directory", "directory is in use", "directory not empty", or "disk error".
Returns
1 on success; 0 on failure.

Internal helpers

lba_to_chs / read_sector / write_sector / cluster_to_lba / fat_next_cluster — the low-level disk primitives every public function sits on top of: LBA→CHS conversion using the BIOS-reported geometry, a 3-retry sector read/write (resetting the controller between attempts; write_sector is read_sector's mirror image, BIOS function 0x03 instead of 0x02), cluster-number→LBA conversion for the data area, and FAT12's packed 12-bits-per-entry chain lookup (cluster + cluster/2 gives the byte offset of a 16-bit read; odd clusters take the high nibble via >> 4, even clusters take the low 12 bits via & 0x0FFF).

fat_format_name / scan_sector / fat_iterate_dir / find_child — fat_format_name turns an 11-byte padded on-disk name into a displayable "NAME.EXT" string. scan_sector parses one 512-byte sector's worth of 32-byte directory entries, filtering deleted (0xE5), long-filename (attribute 0x0F) and volume-label entries, and stopping at the first all-zero entry (end of directory). fat_iterate_dir(cluster, ...) is the one function that knows cluster == 0 means "walk the fixed root-directory sectors" and anything else means "walk this cluster chain through the FAT" — every public directory-reading function goes through it. find_child is fat_iterate_dir plus a visitor that stops at the first case-insensitive name match; it's what both fat_change_dir and fat_find_file use to look up one path component.

fat_set_cluster / fat_alloc_cluster / free_chain / fat_flush_fat — the write-side mirror of fat_next_cluster: fat_set_cluster packs a 12-bit value into the same odd/even-nibble layout fat_next_cluster unpacks, fat_alloc_cluster linear-scans for the first cluster whose FAT entry is 0 and immediately marks it end-of-chain so a second allocation can't claim it too, free_chain walks a chain setting every entry back to 0, and fat_flush_fat writes the in-memory FAT buffer back to every on-disk FAT copy (not just the one cached at init), since real FAT12 keeps fat_count redundant copies in sync.

walk_dir_raw / dir_search_visitor / any_entry_visitor / dir_is_empty — walk_dir_raw is fat_iterate_dir's write-side counterpart: same root-vs-cluster-chain dispatch, but the visitor sees every 32-byte slot's raw bytes and on-disk location (sector LBA + byte offset) rather than a parsed fat_dirent_t, since creating/deleting entries needs to write back to that exact spot. dir_search_visitor finds an existing name match and the first reusable slot (deleted or past-the-end) in one pass, which is what every create-type function below is built on. dir_is_empty is walk_dir_raw plus a visitor that stops at the first real entry.

grow_dir_and_get_slot / write_chain / partial_write_in_cluster / append_to_chain — grow_dir_and_get_slot chains a new zeroed cluster onto a (non-root) directory that's out of free slots. write_chain allocates clusters one at a time and fills them from a data buffer, used for both a fresh overwrite and the tail end of an append. partial_write_in_cluster does a read-modify-write of just the bytes at some byte offset within one cluster — needed because an append's first write usually lands mid-cluster, not at a sector boundary. append_to_chain composes the two: top up whatever space is left in the file's last cluster via partial_write_in_cluster, then hand any remainder to write_chain and link the two chains together.

format_name_83 / build_dirent_raw / write_dirent_raw / resolve_parent / prepare_create — format_name_83 is fat_format_name's inverse: validates and pads a user-typed "NAME" or "NAME.EXT" into the 11-byte on-disk form, rejecting anything that doesn't fit 8.3. build_dirent_raw / write_dirent_raw assemble a 32-byte entry and write it to a known location. resolve_parent is fat_change_dir's path-walking logic with the last component left unresolved (it's the name being created, so it need not exist yet); prepare_create wraps that plus format_name_83 plus a dir_search_visitor pass into the one call fat_mkdir, fat_create_file and fat_write_file all start with.
