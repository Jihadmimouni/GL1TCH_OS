The interactive command shell
Overview x86 kstring console keyboard calc fat shell entry / kmain Architecture ↗

Defined in: src/kernel/shell.c, src/kernel/shell.h

The only module that depends on all the others. Intentionally "dumb": read a line, split it into words, match the first word against a fixed command table. All real behavior lives in whichever module owns the relevant state — fat.c for ls/cd/pwd/ cat, calc.c for calc.

Function detail

void shell_run(void)

The only public function in this module — an infinite loop that prints the prompt (GL1TCH: + fat_get_cwd + > ), reads a line via read_line, and dispatches it to one of the command handlers below based on the first word.

Returns
Never returns.

Internal helpers

cmd_ls / ls_visitor — prints <DIR> or a right-padded byte size for each entry from fat_list_cwd.

cmd_pwd, cmd_cd — thin wrappers that print a usage message when called with no argument, and the driver's error message on failure.

cmd_cat / cat_sink — resolves the path via fat_find_file, then reads it via fat_read_file with a sink that writes each byte through con_putc, inserting a \r before every \n so the file's line breaks render correctly on the BIOS console.

cmd_calc — forwards to calc_eval and prints either the integer result or the error message.

cmd_help — static text listing every command.

tokenize(char *line, char *argv[], int max_args) — splits line into words by overwriting each run of spaces with a single NUL in place, recording a pointer to the start of each word in argv. This mutation is exactly why shell_run keeps a second, untouched copy of the line (raw) for commands that need their original free-form remainder.

rest_after_first_token(char *line) — skips the first whitespace-delimited word, then any following spaces, and returns a pointer to what's left: calc's expression and echo's text, both of which may themselves contain spaces that tokenize would otherwise have split on. Must be called on the untokenized raw copy of the line, never on line after tokenize has run over it — calling it on the tokenized buffer was exactly the bug described in the 2026-10-06 report (calc/echo always failing with a usage error).
