x86

BIOS calls and 32-bit math runtime helpers

Defined in: src/kernel/x86.asm, src/kernel/x86.h

The only module that executes a BIOS interrupt or a raw CPU instruction — everything else reaches hardware only through these cdecl wrappers, so there is exactly one place to look when something at the BIOS boundary misbehaves. Every function uses the _cdecl convention, which matters here because the 8086 push instruction can't push a single byte: even a uint8_t argument occupies a full 16-bit stack slot, which is what lets the fixed [bp+N] offsets in the assembly line up with C's argument order.

Function detail

void x86_putc(char c)

ah=0x0E; al=c; bh=0 → int 10h (BIOS teletype output). Writes one character to the screen at the current cursor position and advances the cursor. Does not translate \n to \r\n — callers (console.c) are expected to emit both when they want a newline.

c
The character to write.
Returns
Nothing.

void x86_clear_screen(void)

ax=0x0003 → int 10h — sets video mode 3 (80x25 text), which clears the screen as a side effect.

Returns
Nothing.

uint16_t x86_getkey(void)

ah=0 → int 16h — blocks until a key is pressed.

Returns
The raw BIOS result: scan code in the high byte, ASCII in the low byte. keyboard.c only looks at the low byte.

void x86_reboot(void)

jmp 0FFFFh:0 — a far jump straight into the BIOS entry point. Never returns.

int x86_disk_reset(uint8_t drive)

ah=0, dl=drive → int 13h. Called before retrying a failed read, and once up front in fat_init.

drive
BIOS drive number (the boot drive, passed down from stage2).
Returns
1 on success, 0 on failure (BIOS carry flag set).

int x86_disk_params(uint8_t drive, uint16_t *sectors_per_track, uint16_t *heads)

ah=8h, dl=drive, es:di=0:0 → int 13h. Asks the BIOS for the drive's actual geometry rather than trusting a hardcoded value; es:di is zeroed first as a defensive workaround for BIOSes that read the floppy parameter table through it even though this call shouldn't need it.

drive
BIOS drive number.
sectors_per_track
Out: filled with the reported sectors/track.
heads
Out: filled with the reported head count.
Returns
1 on success, 0 on failure.

int x86_disk_io(uint8_t op, uint8_t drive, uint16_t cylinder, uint8_t head, uint8_t sector, void *buffer)

ah=op (02h read / 03h write), al=1, es:bx=ds:buffer → int 13h. Reads or writes exactly one 512-byte sector at an explicit CHS address, in one attempt. fat.c owns the LBA→CHS conversion and the retry-on-failure loop; this function just does the one BIOS call and reports whether it worked.

op
0x02 to read, 0x03 to write.
drive
BIOS drive number.
cylinder
0-based cylinder number.
head
0-based head number.
sector
1-based sector number (CHS sectors are 1-indexed, unlike LBA).
buffer
Pointer to a 512-byte buffer in the kernel's own segment (passed as es:bx with es set to ds).
Returns
1 on success, 0 on failure.

Internal helpers

__U4M / __I4M / __U4D / __I4D — not called directly; Open Watcom's 16-bit codegen emits calls to these exact names for any uint32_t/int32_t multiply or divide, since the build links no default runtime library (NODEFAULTLIBS in linker.lnk) that would normally provide them. Convention: operand 1 in dx:ax, operand 2 in cx:bx, result in dx:ax (plus cx:bx for the divide's remainder). __U4M/__I4M share one implementation — the low 32 bits of a multiply are the same whether the operands are signed or unsigned — while __U4D/__I4D differ only in whether the dividend is sign-extended (cdq) before dividing.
