GL1TCH OS — code reference

Every function in src/kernel/, grouped by module, with what it does and why it's shaped that way

This lists the kernel's public API module by module (bottom of the dependency graph first), plus the significant internal (static) helpers where knowing they exist saves someone re-deriving them. For why the modules are layered this way, see architecture.html — this page is the function-level companion to that one.

x86.asm / x86.h

The only module that executes a BIOS interrupt or a raw port/CPU instruction. Every function is _cdecl so the stack layout matches what C expects (every argument, even a uint8_t, occupies a full 16-bit stack slot — the 8086 push instruction can't push a byte).

void x86_putc(char c)

ah=0x0E; al=c; bh=0 → int 10h (BIOS teletype)

Writes one character to the screen at the current cursor position, advancing the cursor. Does not translate \n to \r\n — callers (console.c) are expected to emit both.

void x86_clear_screen(void)

ax=0x0003 → int 10h (set video mode 3: 80x25 text, clears screen)

uint16_t x86_getkey(void)

ah=0 → int 16h (blocking key read)

Blocks until a key is pressed. Returns the raw BIOS result: scan code in the high byte, ASCII in the low byte. keyboard.c only looks at the low byte.

void x86_reboot(void)

jmp 0FFFFh:0 (far jump into the BIOS entry point)

Never returns.

int x86_disk_reset(uint8_t drive)

ah=0, dl=drive → int 13h

Resets the disk controller. Returns 1 on success, 0 on failure (carry flag set). Called before retrying a failed read, and once at fat_init.

int x86_disk_params(uint8_t drive, uint16_t *sectors_per_track, uint16_t *heads)

ah=8h, dl=drive, es:di=0:0 → int 13h

Asks the BIOS for the drive's real geometry rather than trusting a hardcoded value — es:di is zeroed first as a workaround for BIOSes that read the floppy parameter table through it even though this call shouldn't need it. Returns 1 on success.

int x86_disk_io(uint8_t op, uint8_t drive, uint16_t cylinder, uint8_t head, uint8_t sector, void *buffer)

ah=op (02h read / 03h write), al=1, es:bx=ds:buffer → int 13h

Reads or writes exactly one 512-byte sector at an explicit CHS address. fat.c owns the LBA→CHS conversion (see lba_to_chs below) and the retry loop; this function does one attempt and reports success/failure.

__U4M / __I4M / __U4D / __I4D (compiler runtime helpers, not called directly)

convention: operand 1 in dx:ax, operand 2 in cx:bx, result in dx:ax (+ cx:bx remainder for divide)

Open Watcom's 16-bit codegen emits calls to these specific names for any uint32_t/int32_t multiply or divide, since the build links no default runtime library that would normally provide them (NODEFAULTLIBS in linker.lnk). __U4M/__I4M share one multiply implementation (the low 32 bits of a multiply are the same whether signed or unsigned); __U4D/__I4D differ only in whether the dividend is sign-extended first (cdq) before the divide.

kstring.c / kstring.h

Freestanding string/number helpers with no dependencies on any other kernel module. Deliberately not named memcpy/memset/strlen/strcmp/etc.: Open Watcom recognizes those exact names as compiler intrinsics and can emit a call using a different (register-based) calling convention than the _cdecl one actually defined here — silently corrupting arguments. Distinct names sidestep the trap entirely.

void mem_set(void *dst, uint8_t value, uint16_t n)

Fills n bytes starting at dst with value. Byte-at-a-time; there's no bulk rep stosb path since the kernel never fills anything large enough for that to matter.

void mem_copy(void *dst, const void *src, uint16_t n)

Copies n bytes. Does not handle overlapping ranges (no memmove semantics) — nothing in this kernel needs that.

uint16_t str_len(const char *s)

int str_cmp(const char *a, const char *b)

Case-sensitive, like strcmp: 0 if equal, otherwise the sign of the first differing byte's difference. Used for command-name matching in shell.c and path segments like "."/".." in fat.c.

int str_ncmp(const char *a, const char *b, uint16_t n)

int str_icmp(const char *a, const char *b)

Case-insensitive compare (via to_upper on each byte). Used by fat.c's find_child so typing cd src matches a directory entry that FAT stores as SRC.

void str_copy(char *dst, const char *src)

Like strcpy — no bound on dst's size; callers are responsible for sizing buffers correctly (they all do, with fixed small buffers).

char* str_chr(const char *s, char c)

char to_upper(char c)

int is_space(char c) / int is_digit(char c)

void u32_to_str(uint32_t v, char *out, uint8_t base)

Converts v to a NUL-terminated string in the given base (10 or 16 in practice; any base up to 36 works since digits beyond 9 map to 'A'..'Z'). Builds digits least-significant-first into a scratch buffer, then reverses into out. v == 0 is special-cased to "0" since the digit loop otherwise produces nothing.

void i32_to_str(int32_t v, char *out)

Writes a leading - for negative values, then delegates to u32_to_str on the magnitude. (Doesn't special-case INT32_MIN, whose magnitude overflows a positive int32_t — not reachable from calc's inputs in practice.)

int str_to_i32(const char **s, int32_t *out)

Parses a run of decimal digits starting at *s, writes the value to *out and advances *s past what it consumed. Returns 0 (and leaves *s/*out untouched) if there's no digit at all at the start — this is calc.c's number token.

console.c / console.h

Depends only on x86.h. Turns characters and numbers into BIOS teletype calls.

void con_putc(char c)

Thin pass-through to x86_putc. (Kept as a separate call, rather than every module calling x86_putc directly, so console-level behavior like line-ending translation has one place to live if it's ever needed.)

void con_puts(const char *s)

Writes a NUL-terminated string one character at a time. Every string literal printed by the shell already embeds \r\n explicitly — this function does no translation.

void con_print_u32(uint32_t v, uint8_t base) / void con_print_i32(int32_t v)

Format into a small stack buffer via u32_to_str/i32_to_str, then con_puts it. (There's no variadic con_printf: on this 16-bit target int is 16 bits but int32_t is 32, and a hand-rolled varargs reader has no prototype to promote a literal/variable to the right width — a mismatched call site would silently misread the stack. Explicit typed print functions avoid that class of bug entirely.)

keyboard.c / keyboard.h

Depends on x86.h (for key reads) and console.h (to echo what's typed).

void read_line(char *buf, uint16_t max_len)

Reads and echoes characters via x86_getkey until Enter (ASCII 0x0D). Backspace (0x08) erases the last character both in buf and on screen (writes backspace, space, backspace to visually erase the glyph). Printable ASCII (0x20–0x7E) is appended if there's room (silently dropped once max_len - 1 characters are buffered — the line is simply truncated, not an error). Anything else (arrow keys, function keys, etc.) is ignored. Result is always NUL-terminated, and a trailing \r\n is written once Enter is seen.

calc.c / calc.h

Depends only on kstring.h. A standalone recursive-descent evaluator — no knowledge of the console or shell, which is what makes it independently testable in isolation. Grammar: expr := term (('+'|'-') term)*, term := factor (('*'|'/') factor)*, factor := ('+'|'-') factor | '(' expr ')' | number — standard precedence, right down to unary minus binding to a factor so -2*3 parses as (-2)*3, not -(2*3) (same answer here, but the structure is what you'd want for, e.g., -2^3 if exponentiation were ever added).

int calc_eval(const char *expr, int32_t *out, const char **err_msg)

The only public entry point. Returns 1 with *out set on success, or 0 with *err_msg pointing at a short static string ("division by zero", "missing closing parenthesis", "invalid number", "expected a number or '('", "unexpected trailing characters"). Internally resets three file-scope parser globals (g_cur, g_error, g_errmsg) before parsing — the grammar is a straight-line recursive descent with no backtracking, so a simple error flag that short-circuits remaining parsing is enough; there's no error-recovery or multiple-error reporting.

static int32_t parse_expr/parse_term/parse_factor(void) (internal)

One function per grammar rule, each consuming from the shared g_cur cursor and looping (not recursing) for the repeated (op term)* parts, so a long chain like 1+2+3+4 doesn't nest the call stack at all. skip_ws() is called at each point whitespace may legally appear.

fat.c / fat.h

Depends on x86.h (disk I/O) and kstring.h (name comparison/copying). Owns all on-disk and current-directory state as file-scope statics — nothing here is reentrant or thread-safe, which is fine since the kernel has exactly one execution context.

int fat_init(uint8_t drive)

Call once, with the boot drive number the bootloader handed the kernel. Resets the disk, asks the BIOS for real geometry (x86_disk_params, falling back to 18 sectors/track and 2 heads — standard 1.44MB floppy values — if the BIOS reports 0 for either), reads the boot sector and parses the BPB fields it needs directly by byte offset (bytes/sector at 0x0B, sectors/cluster at 0x0D, reserved sectors at 0x0E, FAT count at 0x10, root entries at 0x11, sectors/FAT at 0x16 — read as raw bytes rather than through a C struct, which sidesteps any compiler padding/alignment surprises), derives the root directory and data area locations, and caches up to 9 FAT sectors (this project's fixed floppy layout) in a static buffer. Returns 0 if any disk read fails.

void fat_list_cwd(fat_visitor_t visitor, void *ctx)

Calls visitor(entry, ctx) for every real file/subdirectory entry in the current directory (skips volume labels, long-filename fragments, deleted entries, and ./..). shell.c's ls is the only caller.

void fat_get_cwd(char *out)

Writes the current path ("/" at the root, "/sub/dir" otherwise) by joining the names on the internal directory stack. Used both for pwd and for the shell's prompt.

int fat_change_dir(const char *path, const char **err_msg)

Resolves path (absolute if it starts with /, otherwise relative to the current directory), one /-separated component at a time, against a temporary copy of the directory stack. Only if every component resolves (and is actually a directory, and the stack doesn't exceed its fixed 8-level depth) does it commit the copy back as the real current directory — so a failing multi-component path like cd a/b/nope leaves the shell exactly where it started. . is a no-op, .. pops a level (clamped at the root; it never underflows).

int fat_find_file(const char *path, fat_dirent_t *out, const char **err_msg)

Same path-walking idea as fat_change_dir, but the last component only has to exist (it's returned in *out regardless of type, then rejected with "is a directory" if it turns out to be one) while every earlier component must be a directory. .. mid-path is deliberately unsupported here (distinct error message) since this function doesn't carry a directory-stack copy to pop like fat_change_dir does.

int fat_read_file(const fat_dirent_t *entry, fat_sink_t sink, void *ctx)

Walks entry's cluster chain, calling sink(data, len, ctx) once per sector read (capped at the file's remaining declared size, so the last partial sector doesn't hand back trailing garbage past EOF). shell.c's cat is the only caller, with a sink that re-inserts \r before each \n for display.

Internal helpers (static)

lba_to_chs / read_sector / cluster_to_lba / fat_next_cluster

The low-level disk primitives every public function sits on top of: LBA→CHS conversion using the BIOS-reported geometry, a 3-retry sector read (resetting the controller between attempts), cluster-number→LBA conversion for the data area, and FAT12's packed 12-bits-per-entry chain lookup (cluster + cluster/2 gives the byte offset of a 16-bit read; odd clusters take the high nibble via >> 4, even clusters take the low 12 bits via & 0x0FFF).

fat_format_name / scan_sector / fat_iterate_dir / find_child

fat_format_name turns an 11-byte padded "NAMEEXT" on-disk entry into a displayable "NAME.EXT" string. scan_sector parses one 512-byte sector's worth of 32-byte directory entries, filtering out deleted (0xE5), long-filename (attr 0x0F) and volume-label entries, stopping at the first all-zero entry (end of directory). fat_iterate_dir(cluster, ...) is the one function that knows cluster == 0 means "walk the fixed root-directory sectors" and anything else means "walk this cluster chain through the FAT" — every other directory-reading function goes through it. find_child is fat_iterate_dir plus a visitor that stops at the first case-insensitive name match, used by both fat_change_dir and fat_find_file.

shell.c / shell.h

The only module that depends on all the others. Intentionally "dumb": read a line, split it into words, match the first word against a fixed table. All real behavior lives in whichever module owns the relevant state.

void shell_run(void)

The only public function — an infinite loop that prints the prompt (GL1TCH: + fat_get_cwd + > ), reads a line, and dispatches. Never returns.

Internal command handlers (static)

cmd_ls / ls_visitor

Prints <DIR> or right-padded byte sizes per fat_list_cwd entry.

cmd_pwd

fat_get_cwd + newline.

cmd_cd

Prints a usage message if called with no argument, otherwise forwards to fat_change_dir and prints its error message on failure.

cmd_cat / cat_sink

Resolves the path via fat_find_file, then fat_read_file with a sink that writes each byte through con_putc, inserting a \r before every \n so the file's line breaks render correctly on the BIOS console.

cmd_calc

Forwards to calc_eval and prints the integer result or the error message.

cmd_help

Static text listing every command.

tokenize(char *line, char *argv[], int max_args)

Splits line into words by overwriting each run of spaces with a single NUL, in place, and records a pointer to the start of each word in argv. Mutates line — this is exactly why shell_run keeps a separate untouched copy (raw) for commands that need their original free-form remainder.

rest_after_first_token(char *line)

Skips the first whitespace-delimited word, then any following spaces, and returns a pointer to what's left — calc's expression and echo's text, which may themselves contain spaces that tokenize would otherwise have split on. Must be called on the untokenized raw copy of the line, not on line after tokenize has run over it (see the bug this caused, in the 2026-10-06 report).

entry.asm / kernel.c

entry (assembly label, the kernel's actual load-time entry point)

What stage2 jumps to. Sets ds/es/ss to cs (the kernel's single 64KB segment — code, data and stack all share it) and the stack pointer to near the top of that segment, then calls kmain(boot_drive) with the boot drive number stage2 left in dl. If kmain ever returned, falls into cli; hlt in a loop — it doesn't, since shell_run never returns either.

void kmain(uint16_t boot_drive)

The C side of the handoff: clears the screen, prints the banner, calls fat_init((uint8_t)boot_drive) (printing a warning rather than halting if it fails — the shell still starts, just without a working filesystem), then shell_run().
